
# Generative AI Risk Assessment Matrix

**Phase:** 1 - Govern and Map  
**Framework Mapping:** NIST AI RMF (MAP 3.1, MEASURE 1.1) | NIST AI 600-1 (Generative AI Profile)

This assessment evaluates the specific risks introduced by Generative AI in the NovaCloud environment, mapping them to the NIST AI 600-1 risk categories.

## Risk Assessment Matrix

| Risk ID    | Risk Scenario                                                                                                                                                             | NIST AI 600-1 Category                               | Likelihood | Impact       | Overall Risk | Proposed Mitigation                                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ---------- | ------------ | ------------ | ---------------------------------------------------------------------------------------------------------------------- |
| **RAI-01** | **Data Leakage via Model Training:** External LLM vendor ingests proprietary code and API keys, outputting them to unauthorized third parties                             | _Information Security (IS)_ / _Data Privacy (DP)_    | **High**   | **Critical** | **Critical** | Implement semantic filtering; negotiate zero-retention API contracts; enforce Secret Scanning on all Git commits.      |
| **RAI-02** | **Vulnerable Code Generation:** AI coding assistant hallucinates or suggests insecure code (e.g., SQL injection vectors), which developers blindly merge into production. | _Confabulation (CB)_ / _Human-AI Configuration (HC)_ | **Medium** | **High**     | **High**     | Mandate strict human-in-the-loop (HITL) code reviews; integrate SAST/DAST tools in the CI/CD pipeline prior to merge.  |
| **RAI-03** | **Shadow AI Data Exposure:** Employees paste customer PII or financial data into public, unvetted consumer LLMs (e.g., ChatGPT, Claude) to format text or write emails.   | _Information Security (IS)_                          | **High**   | **Medium**   | **High**     | Deploy endpoint DLP (Data Loss Prevention) to block pasting into unauthorized AI domains; issue Acceptable Use Policy. |
| **RAI-04** | **Prompt Injection:** Malicious actors embed hidden instructions in user-submitted support tickets, manipulating internal GenAI tools to execute unauthorized actions.    | _Information Security (IS)_                          | **Low**    | **High**     | **Medium**   | Isolate AI agent permissions (Principle of Least Privilege); sanitize all external inputs before AI processing.        |

## Key Findings & Immediate Action Items

1. **Critical Vulnerability Identified:** The current OAuth permissions model allows third-party AI agents unvetted access to restricted data environments.
    
2. **Missing Guardrails:** There is no data masking or secret sanitization occurring _before_ data leaves the NovaCloud perimeter and enters the AI vendor's API.
    
3. **Next Step (Phase 2):** We must immediately design an AI IAM policy and technical data masking controls to mitigate **RAI-01** and **RAI-03**.

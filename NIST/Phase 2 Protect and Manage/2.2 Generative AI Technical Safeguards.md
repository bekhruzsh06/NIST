## Architecture Guardrails

To enforce administrative policies technically, NovaCloud implements the following pipeline controls for all outgoing LLM API and incoming AI-generated code


### 1. Pre-Commit Secret Sanitization

- **Tooling:** Implement `detect-secrets` or GitHub Advanced Security

- **Enforcement:** Hard-blocking pre-commit hook. Any commit containing identifiable AWS keys, SSH keys, or database credentials is automatically rejected before entering the repository (preventing AI ingestion)

### 2. LLM API Gateway & Data Masking

- **Tooling:** All internal applications requesting external LLM APIs must route through the centralized AI API Gateway.
    
- **Enforcement:** The gateway utilizes regex and NER (Named Entity Recognition) to automatically mask sensitive data patterns (e.g., standard API key formats, SSNs) with placeholders (e.g., `[REDACTED_AWS_KEY]`) before the prompt leaves the NovaCloud network.
    

### 3. Vendor Data Retention Controls

- **Enforcement:** All procured AI tools must operate under an Enterprise agreement with an explicit "Zero-Data Retention" API configuration. Vendor telemetry, model training on customer data, and prompt logging by the third party must be disabled at the API level.
